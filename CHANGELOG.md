# Changelog

## Unreleased

- `missionbase-agent project link <project-id>` now writes `.missionbase/project.json` at the git root above `--cwd` (or the current folder), or in the folder outside git, with the keys in the `missionbase-setup` order (`team_id`, `team_name`, `project_id`, `project_name`, `box_id`, `box_name`). It refuses to replace a link to a different project, or a file that isn't valid JSON, unless `--force`, drops stale team keys for a personal project, and takes `--json`. Added `project unlink [--cwd DIR] [--json]`, which removes the link (keeping any other keys) and the file when nothing is left. `project link` and `unlink` are in the help.
- Added `missionbase-agent task create ... --start [--terminal [machine/]tN] [--force]`, which creates the task and then starts work on it like `task start` (default terminal `$HC_TERMINAL_ID`). The terminal is resolved before the task is created (exit 4 and no task when `hc` can't); a start conflict after creating exits 3. It prints the `task start --json` response. `--start` wins over `--status`.
- `task create` no longer needs `--project`: the project resolves from `--project`, then `.missionbase/project.json` from `--cwd DIR` or the current folder, then the machine default, like `tasks ls` (exit 5 when none does).
- Added `missionbase-agent task create --status KEY` (`backlog`, `planning`, `todo`, `in_progress`, `complete`, `not_doing`) to create a task in a status other than To Do. The server validates the key; `needs_attention` is refused before sending.
- `missionbase-agent task create` and the other older commands that always print the server's JSON (`task show`, `update`, `message`, `assign`, `unassign`, `status`, `move`, `complete`, `messages`, `participants`, and `projects create`) now accept `--json` instead of rejecting it, and print the same JSON with or without it. `task create` prints `{"task": {...}}`, so scripts can read `.task.id`.

- Added `missionbase-agent projects notes show|edit|append|history [project-id]` for a project's notes (one Markdown page with version history). The project defaults to `--project`, then `.missionbase/project.json`, then the default project. `edit --body-file PATH [--base-version ID]` replaces the page (a 409 when someone else changed it since the base version exits 3); `append --body-file PATH [--date YYYY-MM-DD]` adds a dated entry under `## Log` dated today on this machine; `history` lists versions with who, what and +/- lines. All take `--json`.

- `task questions` (and `--wait`) saves the images in an answer to `~/.cache/missionbase/answers/<task-id>/` and prints, under the answer, "This answer includes 2 images. Look at them before acting: …" with their paths. An image-only answer reads `Answer: [2 images]`. `--json` adds `local_path` (or `download_error`) to each of a question's `answer_attachments`. Downloads use the signed image URL without the API key, reuse saved files, and never fail the command: an image that can't be saved is listed by URL.

- Added `missionbase-agent project watch --terminal tN [--cwd DIR | --project ID]`, `project watch --off` and `project watch` (show). A watch signs a terminal on this machine up for the project's activity, which the missionbase-herdr bridge types into it as a digest when it's idle. It is kept in `~/.config/missionbase-herdr/watches.json` (`$MISSIONBASE_HERDR_WATCHES` overrides), one terminal per project, with the acting agent's slug; nothing is stored in Missionbase.

- Boxes are now called projects. Added `projects ...` to both CLIs (same subcommands as `boxes ...`, which keeps working), `missionbase project show` beside `box show`, `missionbase-agent agent projects add` beside `agent boxes add`, and `--project` / `--project-id` beside `--box` / `--box-id` (task create, task update, task move, document create, members, tasks, agent projects add). Help and README use the project names.
- Requests go to `/api/v1/projects/...` and send `project_id` / `project_ids`, plus `box_id` / `box_ids` with the same value for older servers. A projects path that an older server does not route (a 404 without the API error envelope) is retried on its `/api/v1/boxes/...` path, and the rest of the run uses the box paths. Responses are read as `project` first, then `box`.
- `.missionbase/project.json` is read as `project_id` / `project_name`, falling back to `box_id` / `box_name`. The `project` object in `project`, `tasks ls` and `task next --json` output carries both pairs (`project_id`, `project_name`, `box_id`, `box_name`), so older Herdr panels keep working.
- Added `missionbase-agent project link <project-id> [--cwd DIR]`, which writes `.missionbase/project.json` with the project's name and team from the server and both the `project_*` and `box_*` pairs, keeping other keys in the file.

- Removed the `needs_attention` status (statuses: `backlog`, `planning`, `todo`, `in_progress`, `complete`, `not_doing`). "Needs you" is now the `needs_you` flag on task payloads (open questions or a live permission prompt). `task status <id> needs_attention` and `missionbase task create|update --status needs_attention` fail before sending, pointing to `task ask`; `tasks ls --status needs_attention` points to `--needs-you`.
- Added `tasks ls --needs-you` (`needs_you=true`). The text output of `tasks ls` and `tasks changes` marks tasks that need you, with the oldest open question when there is one.
- `task attention` asks one question and `task attention clear` dismisses the open questions; neither changes the status. `task ask` prints the unchanged status.
- Added the `planning` task status, between `backlog` and `todo`: the task is being planned with its owner, not built. `task status <id> planning`, `missionbase task create|update --status planning` and `tasks ls --status planning` accept it, the help and README list it, and `task next` never picks a Planning task (the server skips it). `task start` leaves a Planning task in Planning.
- Added `missionbase-agent task ask <task-id> "question" [--context TEXT] [--option TEXT]...` and `task ask <task-id> --file PATH` (a JSON array of 1 to 5 `{"body", "context", "options"}` objects) to ask the task's owner questions. The task moves to Needs Attention; the output lists the questions, the new status and the task page link.
- Added `missionbase-agent task questions <task-id> [--status open|answered|dismissed[,...]]` to list a task's questions with their answers, and `--wait [--timeout DURATION]` to poll every 20s until none are open. A `--wait` timeout exits with code 6.
- `tasks ls`, `tasks changes` and `task next` show "N questions" for tasks with open questions.
- API errors now list the server's `error.details` messages (for example the per-question errors from `task ask`).
- `task attention` is documented as asking one question; the server no longer posts it as a comment.

- Removed task status ids, which Missionbase no longer has. Statuses are now fixed keys (`backlog`, `todo`, `in_progress`, `needs_attention`, `complete`, `not_doing`). `--task-status-ids` (`boxes tasks`, both CLIs), `--task-status-id` (`task create`/`task update` in `missionbase`, and `discussion convert` in both) now fail with a pointer to `--status KEY` / `--status-category`. The `boxes task-statuses` help and the README describe the fixed list, and `task move` keeps the task's status.
- Added agent work commands for Herdr agents: `task start` (records the hc machine and terminal, `--force` to take over), `task stop`, `task attention` / `task attention clear`, `task next`, `tasks ls`, `tasks changes` and `project [show|default]`, all with `--json`. Project resolution uses `--project`, then `.missionbase/project.json`, then the machine's `default_project`.
- An HTTP 409 now exits with code 3. `task start` exits 4 when `hc` cannot resolve the terminal, and `tasks ls` exits 5 when no project resolves. `auth status` shows the default project.
- Added `missionbase-agent task update <task-id> --body-file PATH` to replace a task description (sent as `body`, like `task create --body-file`), and `--title` to rename a task.
- Added `missionbase-agent agent image set AGENT --file PATH`, `agent image clear AGENT --yes`, and `agent create --image PATH` for agent profile images (PNG, JPEG, WEBP; max 5 MB; the server stores them as JPEG resized to fit within 500×500).
- Added `missionbase-agent boxes create --name NAME --team TEAM_ID` for creating team-owned boxes, with optional Markdown description, kind, status, and visibility.
- Reported native Pi session names on registration, heartbeat, and `/name` changes so Missionbase can distinguish sessions by their human-readable names.
- Replaced the Pi bridge's request/response capture with complete, resumable active-branch transcript synchronization, including existing user, assistant, tool, shell, and summary entries and durable deduplication of remote message injection.
- Added `missionbase-agent pi agents` and `missionbase-agent pi --agent SLUG -- ...` for local Pi sessions bound to an explicit Missionbase agent identity, including preflight validation and protection against accidental user-acting CLI calls. The launcher accepts `--continue`/`-c` for the current directory's most recent session, `--resume`/`-r` for Pi's interactive session chooser, and `--session SESSION`/`-s SESSION` for a specific session path or ID.
- Added `missionbase pi --team TEAM ...` and `--one-shot` passthrough for the interactive runner launcher.
- Added managed agent-instruction commands: `missionbase-agent agent instructions show|publish|activate`, with exact body-file content preserved for hash verification.
- Added agent activity query tooling: `missionbase-agent activity <box|team> <id>` and `missionbase-agent boxes activity <box-id>` support time ranges, duration shortcuts, actor/subject/action filters, cursor pagination, concise default output, and `--json` raw output.
- Added canonical-id discussion messaging commands (`discussion show/message`) plus document/file message helpers; `conversation show/message` is now documented as a deprecated alias.
- Added scratchpad fetch/update commands to both CLIs: `missionbase scratchpad show|update|edit` and `missionbase-agent scratchpad show|edit --user USER`.
- Switched task creation opening text to `body`: `missionbase task create --body TEXT` and `missionbase-agent task create --body-file PATH`; task updates now only change task metadata such as deadline/schedule/status/box/title.
- Added Missionbase user CLI catch-up phase 5 notes/document/raw helpers: `missionbase notes search`, `missionbase boxes documents create`, `missionbase document show`, `missionbase document update`, plus clearly warned raw `post`/`patch`/`delete` signed-in-user helpers.
- Updated `missionbase --help` and README user CLI documentation to describe day-to-day Missionbase workflows beyond low-level API access.
- Added `missionbase work` for user-acting current-work overviews via `/api/v1/users/work`, including current user, assigned/open tasks, unread conversations, and metadata.
- Added Missionbase user CLI catch-up phase 3 lookup, user assignment/unassignment, and task participant commands: `missionbase users lookup`, `missionbase task assign`, `missionbase task unassign`, `missionbase task participants list`, and `missionbase task participants add --user`.
- Added user mention resolution for numeric ids and team-scoped `@mention`s using only user-facing endpoints.
- Added Missionbase user CLI catch-up phase 2 safe write commands for task create/update/status/complete/message, discussion messages, and box discussion creation.
- Added shared Markdown body normalization and attachment multipart helpers for user CLI writes, with PNG/JPEG/GIF/WEBP validation and a 5 MB file limit.
- Added Missionbase user CLI catch-up phase 1 read-only commands for teams, boxes, box tasks/discussions/statuses, user task listings, task discussion messages, conversations, and discussion conversations.
- Updated user CLI auth/request handling so user mode uses only user credentials and never sends `X-Missionbase-Agent-Slug` or reads agent directory config.
- Kept `missionbase me` user-only by removing the previous `/api/v1/agent/me` fallback.
